# 实时通知场景开发计划

根据服务类型表格分析，以下场景适合使用 Android 16 Live Updates 实时通知。

## 分析标准

实时通知适用条件：
1. ✅ 用户主动发起的活动
2. ✅ 有明确的开始和结束
3. ✅ 需要实时跟踪进度
4. ✅ 时效性强，用户需要持续关注

### ⚠️ 不太适合（仅提醒类，非持续进度）
- 演出/电影购票 - 一次性提醒，非持续跟踪
- 购物/支付尾款 - 一次性提醒
- 酒店入住 - 一次性提醒
- 生活缴费 - 一次性提醒
- 服务到期 - 一次性提醒
- 消费记录 - 一次性提醒
- 余额提醒 - 一次性提醒
- 用药提醒 - 定时提醒，非进度

## 通用开发模板

### 模板1：简单进度（下载/充电类）
```
进度条：[========>    ] 80%
```

### 模板2：分段进度（外卖/打车类）
```
[●下单] → [●准备] → [●取餐] → [○配送]
         ↑ 当前位置
```

### 模板3：多站点（火车/公交类）
```
[起点]●————●————●————●[终点]
      站1   站2   站3
         🚄 当前位置
```

### 模板4：计时器模式（租赁/运动类）
```
⏱️ 01:23:45
💰 ¥5.00
```

---

## 备注

- 实时通知仅在 Android 16+ 生效，低版本需回退到普通通知
- 所有场景都需要用户主动触发，不能用于推送广告
- 考虑添加取消/结束按钮，让用户可以关闭通知
